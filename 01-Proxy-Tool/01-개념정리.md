## 01. Proxy Tool 개념 정리
   ### 1-1. Proxy의 정의
    Proxy는 클라이언트와 서버 사이에서 요청과 응답을 중계하는 역할을 한다.
    일반적으로 사용자가 웹 사이트에 접속 -> 브라우저가 웹 서버에 직접 요청을 보냄 -> 서버는 그에 대한 응답 반환. 그러나 Proxy를 사용하면 클라이언트의 요청이 Proxy 서버를 거쳐 웹 서버에 전달되고, 서버의 응답 역시 Proxy를 통해 클라이언트로 돌아옴.
    
    **일반적인 웹 통신**
    클라이언트 -> 웹 서버 -> 클라이언트
    
    **Proxy를 사용하는 웹 통신**
    클라이언트 -> Proxy -> 웹 서버 -> Proxy -> 클라이언트
    proxy는 사용 목적에 따라 요청을 전달하거나 접근을 제어하고, 통신 내용을 기록하는 등 다양한 역할을 수행
    
   ### 1-2. Proxy의 종류
    **Forward Proxy(정방향 프록시)**
    클라이언트 측에서 서버로 보내는 요청 대신 전달. 주로 클라이언트의 인터넷 접근을 관리하거나 요청을 중계하는 데 사용됨.
    
    **Reverse Proxy(역방향 프록시)**
    서버 측 앞에 배치되어 클라이언트의 요청을 받아 내부 서버에 전달. 부하 분산, 캐싱, 보안 등의 목적으로 활용됨. 이번 미션에서 다루는 Brup Suite와 같은 웹 보안 테스트용 Proxy Tool은 브라우저와 웹 서버 사이의 HTTP 통신을 분석하는 데에 중점을 둠.
    
## 02. HTTP 요청과 응답
       Proxy Tool을 이해하려면 먼저 HTTP 통신 구조를 알아야 함.
       HTTP는 클라이언트와 서버가 웹에서 데이터를 주고받을 때 사용하는 프로토콜. 웹 통신은 기본적으로 클라이언트의 요청과 서버의 응답으로 이루어진다.
       
 ### 2.1 HTTP Request
       HTTP 요청은 클라이언트가 서버에 특정 작업을 요구하는 메시지. EX) 사용자가 웹 사이트에서 검색 -> 브라우저는 검색어를 포함한 요청을 서버에 보냄
       
       HTTP 요청 예시
       
       GET /search?q=proxy HTTP/1.1
       HOST: example.com
       각 항목의 의미
       GET: 서버에 리소스를 요청하는 HTTP 메서드
       /search: 요청할 경로
       q=proxy: 검색어를 전달하는 쿼리 매개변수
       HTTP/1.: HTTP 프로토콜 버전
       Host: 요청 대상 서버의 호스트 이름
       
       HTTP 요청 메시지는 요청 라인, 헤더, 빈 줄, 선택적인 본문(Body)로 구성됨.
       
       주요 HTTP 메서드
       
       GET: 리소스 조회
       POST: 데이터 전송 및 처리 요청
       PUT: 리소스 생성 또는 전체 교체
       PATCH: 리소스 일부 수정
       DELETE: 리소스 삭제 요청
       
       GET과 POST는 웹사이트에서 주로 사용되는 메서드지만, 모든 GET 요청이 안전하거나 모든 POST 요청이 보안상 안전한 것은 아님. 실제 보안성은 서버의 처리 방식과 HTTPS 사용 여부 등에 따라 달라짐.
       
   ### 2.2 HTTP Response
   
       HTTP 응답은 서버가 클라이언트의 요청을 처리한 후 반환하는 메시지임.
       
       HTTP 응답 예시
       
       HTTP/1.1 200 OK
       Content-Type: text/html

       <html>
         <body>Search Result</body>
       </html>

       위 예시는 서버가 요청을 정상적으로 처리하고 HTML 데이터를 반환한 상태를 나타냄
       HTTP응답 역시 상태 라인, 헤더, 빈 줄, 선택적인 본문으로 구성

       주요 HTTP 상태 코드
       
       200 OK: 요청이 정상적으로 처리됨
       301 Moved Permanently: 리소스가 영구적으로 이동됨
       302 Found: 다른 URL로 임시 이동
       403 Forbidden: 서버가 요청을 이해했지만 처리를 거부함
       404 Not Found: 요청한 리소스를 찾을 수 없음
       500 Internal Server Error: 서버 내부에서 오류가 발생함

   ## 3. Proxy Tool의 역할과 작동 원리
 ### 3.1 Proxy Tool 이란?
          Proxy Tool은 클라이언트와 웹 서버 사이의 통신을 관찰하고 분석하는 도구
          일반적인 브라우저에서는 화면에 표시되는 결과를 주로 확인. BUT Proxy Tool 을 사용하면 해당 결과가 만들어지는 과정에서 어떤 HTTP 요청과 응답이 오갔는지 확인할 수 있다.
특히 웹 보안 진단에 사용되는 Intercepting Proxy는 요청이나 응답을 중간에서 가로채 확인하고 수정할 수 있다.

   ### 3.2  주요 기능
          1) HTTP 요청 및 응답 확인
             브라우저에서 발생한 HTTP 통신 내용을 확인한다.
             요청 URL, HTTP 메서드, 헤더, 쿠키, 매개변수, 응답 상태 코드 등 분석 가능
             
          2) 요청 가로채기(Intercept)
             클라이언트가 보낸 요청을 서버에 전달하기 전에 일시적으로 중단한다.
             이때 요청 내용을 확인하거나 수정한 다음 서버로 전달할 수 있다.
             
          3) 요청 수정 및 재전송
             기존 HTTP 요청의 일부 값을 변경한 후 다시 전송하고, 서버가 어떻게 응답하는지 비교할 수 있다. -> 이를 통해 서버가 입력값을 올바르게 검증하는지 확인하는 데 도움을 받을 수 있다.
             
          4) HTTP 통신 기록 확인
             웹사이트를 사용하는 동안 발생한 요청과 응답을 기록하고, 필요한 통신을 선택하여 분석할 수 있다.
             
   ### 3.3 HTTPS 통신과 Proxy Tool
   
             HTTPS는 HTTP 통신에 TLS 암호화를 적용하여 전송 중인 데이터를 보호하는 방식이다.
             따라서 HTTPS 통신을 중간에서 단순히 가로챈다고 해서 암호화된 내용을 바로 읽을 수 있는 것은 아니다. Burp Suite 같은 Proxy Tool은 브라우저가 해당 도구의 인증서를 신뢰하도록 설정된 테스트 환경에서 HTTPS 요청과 응답을 분석할 수 있다.
Proxy Tool이 모든 HTTPS 통신을 무조건 복호화할 수 있는 것은 아니며 적절한 설정이 필요하다.

   ## 4. 주요 Proxy Tool 비교
   
             대표적인 Proxy Tool에는 Burp Suite, Fiddler, OWASP ZAP 등이 있다. 세 도구 모두 HTTP 통신을 분석할 수 있지만, 주요 사용 목적과 제공 기능에는 차이가 있다.

### 4.1 Burp Suite

Burp Suite는 PortSwigger에서 개발한 웹 애플리케이션 보안 테스트 도구다.
웹사이트에서 발생하는 요청과 응답을 분석하고, 수정된 요청에 대한 서버의 반응을 확인하는 데 활용된다.

주요 기능
Proxy: HTTP 요청과 응답을 가로채 분석
HTTP history: 통신 기록 확인
Repeater: HTTP 요청을 수정하고 반복 전송
Decoder: 데이터 인코딩 및 디코딩
Intruder: 다양한 입력값을 이용한 테스트 (무료 버전은 기능 제한)

Burp Suite는 무료 Community Edition과 유료 Professional Edition을 제공한다.
Community Edition에서도 Proxy, HTTP history, Repeater 등 주요 수동 테스트 기능을 사용할 수 있다. 다만 자동 웹 취약점 스캐너 등 일부 고급 기능은 Professional Edition에서 제공된다.

### 4.2 Fiddler 

Fiddler는 웹 및 애플리케이션의 HTTP/HTTPS 통신을 분석하고 디버깅하는 도구다.
대표적으로 Fiddler Classic과 Fiddler Everywhere가 있다.

주요 기능

-HTTP/HTTPS 트래픽 수집 및 확인
-요청과 응답의 헤더 및 본문 분석
-통신 오류 분석
-요청 및 응답 내용 수정
-통신 기록 비교 및 디버깅

Fiddler Classic은 Windows 환경에서 사용하는 기존 제품이며, 현재 유지보수 중심으로 제공된다.
Fiddler Everywhere는 Windows, macOS, Linux를 지원하는 제품으로, 다양한 애플리케이션의 통신 분석과 디버깅에 활용할 수 있다.
Fiddler는 보안 분석에도 활용할 수 있지만, 웹 통신 문제를 진단하고 개발 과정에서 오류를 파악하는 용도로도 널리 사용된다.

### 4.3 OWASP ZAP

OWASP ZAP(Zed Attack Proxy)은 웹 애플리케이션의 보안 취약점을 진단하는 오픈소스 도구다.
무료로 사용할 수 있으며 수동 분석과 자동화된 보안 테스트 기능을 제공한다.

주요 기능

History: HTTP 통신 기록 확인
Breakpoints: HTTP 요청과 응답을 중간에서 중단하고 수정
Passive Scan: 통신 내용을 분석하여 잠재적인 보안 문제 탐지
Active Scan: 테스트 요청을 보내 잠재적인 취약점 확인
Spider: 웹사이트의 링크와 경로 탐색

Passive Scan은 통신 메시지를 변경하지 않고 분석한다.
반면 Active Scan은 대상 서버에 테스트 요청을 보내기 때문에 시스템에 영향을 줄 수 있다. 따라서 반드시 허가된 환경에서 사용해야 한다.

### 4.4 세 가지 도구 비교

1)Burp Suite
  목적: 웹 보안 테스트
  HTTP분석: 지원
  요청 수정: 지원
  자동 취약점 진단: Professional에서 지원
  특징: 수동 웹 취약점 분석에 강점

2) Fiddler
   목적: 웹 통신 분석 및 디버깅
   HTTP 분석: 지원
   요청 수정: 지원
   자동 취약점 진단: 주력 기능 X
   특징: 다양한 통신의 오류 분석에 강점

3) OWASP ZAP
   목적: 웹 보안 취약점 진단
   HTTP 분석: 지원
   요청 수정: 지원
   특징: 오픈소스 및 자동화 기능

세 도구는 모두 웹 통신을 분석한다는 공통점이 있으나 Burp Suite와 OWASP ZAP은 웹 보안 테스트에 특화되어 있고 Fiddler는 통신 디버깅에도 중점을 둔다.


## 5. 웹 보안 진단에서 Proxy Tool이 필요한 이유

웹사이트의 보안 문제는 화면에 보이는 기능만으로 파악하기 어려운 경우가 있다.
예를 들어 사용자가 웹페이지에서 입력한 값은 HTTP 요청의 매개변수 형태로 서버에 전달될 수 있다. 이때 서버가 전달받은 값을 적절히 검증하지 않거나 사용자 권한을 올바르게 확인하지 않으면 보안 문제가 발생할 수 있다.

Proxy Tool을 사용하면 요청에 포함된 값과 서버의 응답을 직접 분석할 수 있어 이러한 문제를 조사하는 데 도움이 된다.

### 5.1 접근 권한 검증

일반 사용자가 다른 사용자의 정보나 관리자 기능에 접근할 수 없도록 서버가 권한을 검사하는지 확인하는 것은 웹 보안 진단의 중요한 항목이다. Proxy Tool을 활용하면 허가된 테스트 환경에서 요청을 비교하고, 서버가 접근 권한을 적절하게 검증하는지 분석할 수 있다.

### 5.2 입력값 검증

클라이언트에서 입력을 제한하더라도 HTTP 요청 자체는 별도로 수정될 수 있다. 따라서 브라우저의 입력 제한만 믿는 것이 아니라, 서버에서도 전달받은 데이터를 검증해야 한다. Proxy Tool은 수정된 입력값에 대해 서버가 어떤 응답을 반환하는지 확인하는 데 유용하다.
